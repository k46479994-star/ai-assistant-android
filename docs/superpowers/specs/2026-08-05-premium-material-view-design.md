# Premium Material View Redesign

## 목표

현재 AI 비서 앱의 오프라인 자동 분류, Room 저장, 캘린더 전달, 사용자 학습 규칙을 그대로 유지하면서 전체 화면을 더 정돈된 프리미엄 Material 스타일로 교체한다. 이번 작업은 기능 확장이 아니라 시각적 완성도, 사용성, 정보 구조 개선에 집중한다.

## 범위

이번 단계에서 변경하는 화면은 다음과 같다.

- 홈
- 빠른 입력
- 저장 전 미리보기
- 일정 진입 화면
- 할 일 목록
- 메모 목록
- 설정
- 공통 상단 영역
- 공통 하단 내비게이션

다음 항목은 이번 범위에 포함하지 않는다.

- Jetpack Compose 전환
- 실제 OpenAI 연동
- 이미지·PDF 첨부
- 음성 인식
- 날씨 조회
- 네트워크 통신
- 데이터 모델 변경

## 기술 방향

기존 Android View 구조를 유지한다. 현재 코드 기반의 ViewFactory 패턴과 AppScreen 내비게이션을 보존하고, 화면별 Factory 내부를 Material Components 중심으로 재구성한다.

이 선택의 이유는 다음과 같다.

- 검증된 오프라인 저장·분류 기능을 건드리지 않는다.
- Compose 전환으로 인한 화면과 테스트 전면 재작성 위험을 피한다.
- 기존 Robolectric 테스트를 유지하면서 시각 회귀 테스트를 추가할 수 있다.
- 새 APK를 빠르게 제공할 수 있다.

## 시각 언어

### 색상

- Primary: `#6C4DFF`
- Primary Container: `#EEE9FF`
- Secondary: `#8E78FF`
- Background: `#F7F6FC`
- Surface: `#FFFFFF`
- Text Primary: `#1E1938`
- Text Secondary: `#6D6781`
- Success: `#3EBE7A`
- Warning: `#F59E42`

### 형태

- 주요 카드 모서리: 24dp
- 작은 카드 모서리: 18dp
- 입력창 모서리: 28dp
- 버튼 높이: 최소 52dp
- 카드 그림자: 약한 elevation 2~4dp
- 화면 좌우 여백: 20dp
- 카드 내부 여백: 18~20dp

### 타이포그래피

외부 폰트 파일은 추가하지 않는다. 시스템 산세리프를 사용하고 크기와 굵기로 위계를 만든다.

- 화면 제목: 28sp, Bold
- 섹션 제목: 19sp, Bold
- 카드 제목: 16sp, Medium/Bold
- 본문: 14~15sp
- 보조 문구: 12~13sp

## 홈 화면

### 상단

- 중앙 또는 좌측에 `AI 비서` 브랜드 표시
- 우측에 작은 원형 설정 버튼
- 큰 인사말 `좋은 하루예요`
- 보조 문구 `AI나 인터넷 연결 없이도 오늘의 일을 정리할 수 있어요.`

### 빠른 입력 카드

홈의 핵심 행동이다.

- 한 줄 입력 유도 문구: `할 일, 일정, 메모를 입력하세요...`
- 좌측에 반짝임 아이콘
- 우측에 원형 보라색 실행 버튼
- 누르면 기존 빠른 입력 화면으로 이동
- 음성 아이콘은 시각 요소로 추가하지 않는다. 실제 기능이 없으므로 오해를 만들지 않는다.

### 오늘 마감 할 일

- 섹션 제목과 `더보기`
- 흰색 카드
- 마감 할 일 수와 상태 문구
- 카드 전체를 누르면 할 일 화면으로 이동

### 최근 메모

- 최근 메모가 없으면 친절한 빈 상태 카드
- 메모가 있으면 최대 3개를 제목과 짧은 본문으로 표시
- 카드 또는 `더보기`를 누르면 메모 화면으로 이동

### 빠른 실행

세 개의 작은 카드로 구성한다.

- 일정
- 할 일
- 메모

각 카드는 해당 화면으로 이동한다. 현재 기능에 없는 `모든 항목`, 사진, PDF 등의 메뉴는 추가하지 않는다.

### 오늘의 요약

한 장의 큰 카드 안에 세 개의 요약 칸을 배치한다.

- 오늘 일정: 외부 캘린더 데이터를 읽지 않으므로 `캘린더에서 확인`으로 표시
- 남은 할 일: Room에서 읽은 진행 중 할 일 수
- 최근 메모: 저장된 메모 수 또는 최근 메모 존재 여부

일정 개수를 임의로 표시하지 않는다.

## 빠른 입력 화면

- 큰 제목과 짧은 설명
- 500자 제한의 둥근 다중 행 입력창
- 예시 문장 3개를 작은 칩으로 제공
- 큰 보라색 `분류하기` 버튼
- 오류는 입력창 아래에 붉은 보조 텍스트로 표시
- 서버, 온라인, AI 처리 중이라는 표현을 사용하지 않는다.

## 저장 전 미리보기

기존 편집 기능을 보존한다.

- 상단에 추천 분류 배지
- 일정·할 일·메모 선택은 세그먼트형 컨트롤 또는 Material Spinner 사용
- 제목, 날짜, 시간, 알림 필드를 카드 안에서 구분
- 원문은 별도 연한 배경 카드로 표시
- 저장 버튼은 화면 하단에 크게 배치
- 일정은 `캘린더에서 확인`, 할 일·메모는 `저장`
- 유효하지 않은 상태에서는 저장 버튼 비활성화
- 분류를 수정했을 때만 `이 표현을 기억` 옵션 노출

## 목록 화면

### 할 일

- 상단에 진행 중·완료 필터
- 각 항목은 둥근 카드와 체크박스
- 마감일이 있으면 보조 텍스트로 표시
- 오른쪽 아래 또는 상단에 `추가` 버튼
- 빈 상태에서도 빠른 입력으로 이동 가능

### 메모

- 최신순 카드 목록
- 제목과 최대 80자의 본문 미리보기
- 날짜를 작은 보조 텍스트로 표시
- 빈 상태 카드와 `메모 추가` 버튼

### 일정

- 설치된 캘린더 앱에서 최종 확인한다는 안내 카드
- `새 일정` 버튼은 `일정 추가: `가 입력된 빠른 입력 화면으로 이동
- 앱이 캘린더를 읽는 것처럼 보이는 월간 달력이나 가짜 일정 목록은 표시하지 않는다.

## 설정 화면

- 기본 일정 시간
- 기본 알림 시간
- 저장 전 확인은 항상 켜짐
- AI 사용은 꺼짐, 오프라인 기본 모드
- 학습한 분류 규칙 목록과 삭제 버튼

각 설정 그룹을 별도 카드로 나누며, 숫자 입력 오류는 저장 전에 검증한다.

## 내비게이션

하단에는 기존 다섯 목적지를 유지한다.

- 홈
- 빠른 입력
- 일정
- 할 일
- 메모

선택된 항목은 보라색 배경의 둥근 표시와 진한 텍스트로 강조한다. 미선택 항목은 회색 아이콘·텍스트를 사용한다. 실제 벡터 아이콘을 추가하되, 아이콘만으로 의미가 불명확하지 않도록 짧은 텍스트 라벨을 유지한다.

## 상태와 데이터 흐름

기존 흐름을 변경하지 않는다.

```text
사용자 입력
→ OfflineInputProcessor
→ ClassificationResult
→ PreviewView
→ EventDraft / TaskDraft / NoteDraft
→ CalendarGateway 또는 Room Repository
→ 해당 화면 새로고침
```

UI는 Repository나 Parser 로직을 직접 구현하지 않는다. 각 화면은 기존 Activity 콜백과 Repository 결과만 표시한다.

## 오류 처리

- Room 읽기 실패: 해당 화면 안에 재시도 가능한 오류 카드 표시
- 저장 실패: 미리보기 유지, 저장 버튼 재활성화
- 캘린더 앱 없음: 미리보기 유지, 명확한 오류 문구 표시
- 잘못된 설정 숫자: 저장하지 않고 필드 아래 오류 표시
- 비어 있는 목록: 오류가 아닌 정상 빈 상태로 표현

## 접근성

- 터치 영역 최소 48dp
- 텍스트와 배경 대비 확보
- 아이콘 버튼에 contentDescription 제공
- 색상만으로 선택 상태를 표현하지 않고 배경·굵기·라벨을 함께 사용
- 시스템 글자 크기 확대 시 주요 버튼과 입력창이 잘리지 않도록 Wrap Content와 스크롤 컨테이너 사용

## 테스트 전략

기존 분류·Room·통합 테스트는 그대로 유지한다. 추가 테스트는 다음을 검증한다.

- 홈 화면에 빠른 입력, 할 일, 메모, 요약 섹션이 존재
- 홈 화면에 온라인 상태나 사용 불가능한 AI 기능 문구가 없음
- 하단 내비게이션의 다섯 목적지와 선택 상태
- 빠른 입력 예시 칩이 입력창을 채움
- 미리보기의 유형별 필드 노출과 저장 버튼 상태
- 목록 빈 상태와 데이터 상태
- 큰 글자 크기에서도 주요 화면이 스크롤 가능
- 전체 단위 테스트와 `assembleDebug` 성공

## 완료 기준

- 기존 오프라인 분류·저장 기능이 모두 유지된다.
- 생성된 프리미엄 시안의 분위기를 홈과 공통 컴포넌트에 반영한다.
- 구현되지 않은 기능을 UI가 제공하는 것처럼 보이지 않는다.
- 모든 화면에서 일관된 색상, 여백, 카드, 버튼 체계를 사용한다.
- GitHub Actions의 테스트와 APK 빌드가 성공한다.
- 설치 가능한 새 APK 아티팩트를 제공한다.
